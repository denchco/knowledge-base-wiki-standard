## 0.1.0-rc.4 — 2026-08-09

- Hardened `DKBWS-RUNTIME-002` so managed status exact-matches all twelve governed registration fields, byte-compares the installed LaunchAgent with the generated job contract, requires the exact job loaded, and uses `service:preview` for a fail-closed exact canonical-URL handoff. Live `service:status` is now maintainer-only verification evidence; distribution/CI records the persistent service requirement and capability as not checked.
- Hardened `DKBWS-PROMPT-002` to detect entity-decoded HTML `a`/`area` links and plain GFM-autolinked URLs in addition to Markdown destinations, and added `--managed-live` checks for exact service identity, canonical URL equality, and HTTP 200 from every displayed Wiki route. The `STD-VAL-007` host pre-send limitation remains explicit.
- Hardened `DKBWS-UPDATE-002` with direct-state and terminal-transition invariants, exact issue identity, registry bytes read at the full `registryRevision`, strict release-to-registry ancestry, exact public tag plus `draft: false`/`immutable: true` verification, and stable state/revision/ancestry/release/historical-bridge diagnostics. `pre-registry-local-history` is restricted to the one immutable UK Digital Health `DKBWS-LINK-002` bridge already encoded by workflow v1.
- Migration: persistent consumers refresh all twelve registration values, reinstall the exact current job, and use the status-gated preview command; agent consumers update the response checker and add `--managed-live` for local managed handoffs; proposal consumers validate directly loaded states and may record a release only from the exact registry/ancestry/public-release evidence. New work never copies the historical bridge mode.
- Hardened the public repository with an active no-bypass `main` ruleset requiring pull requests, resolved review threads, merge commits, and the exact GitHub Actions `verify` check while blocking deletion and force pushes. Actions now requires full-SHA references and allows only GitHub-owned actions plus `astral-sh/setup-uv`; secret scanning, push protection, non-provider patterns, validity checks, Dependabot security updates, private reporting, and immutable releases are enabled.
- Shortened only the visible authority-diagram node labels so the renderer-default three-product topology stays within its unchanged 60px contained-overflow ceiling under both macOS and Linux Chromium. Full accessible descriptions, explanatory prose, node/edge topology, text size, styling, centring, and the cross-platform limit remain unchanged; diagnostics now report the measured overflow.
- Selected an exact Node `24.19.0` local/CI runtime instead of the unsafe `>=24` minimum, added `.node-version` plus npm engine-strict enforcement, and made static verification reject the wrong active runtime.
- Reference-qualified Mermaid `11.16.1` with DOMPurify `3.4.13`, Zensical `0.0.53`, and Graphify `0.9.37` under exact Node `24.19.0`; retained vis-network `10.1.0`; raised `npm audit` enforcement from high to moderate; and removed the resolved `STD-VAL-003` compatibility hold after lock, audit, graph, strict-build, and desktop/mobile browser evidence passed.
- Updated the exact Standard Production maintainer dependency from Jujutsu `0.39.0` to reference-qualified `0.44.0` after upstream breaking-change review, disposable colocated command smoke tests, read-only maintainer provenance, and complete verification. Removed the resolved `STD-VAL-004` hold; another pre-1.0 JJ version still requires an explicit qualification pass rather than an inferred version range.
- Added `DKBWS-PROMPT-002`: whenever a development response presents Wiki navigation, it uses a live absolute HTTP(S) URL rooted at the configured canonical Human Wiki origin. The manifest declares `development_response_links: live-wiki`, managed Codex/Claude instructions carry the rule, and the response-link checker plus fixtures reject file, editor, clickable local-filesystem, and repository-relative substitutes.
- Migration: replace clickable file or editor links used as Wiki navigation with verified canonical live routes, after proving the exact service identity and displayed route. A plain repository path remains permitted only to identify a non-Wiki implementation artifact; if a Wiki route is unavailable, disclose that state instead of falling back to a file link.
- Captured response drafts can be checked with `npm run response:links:check -- --base-url <canonical-url>` and violations are nonconforming. Absolute interception of a response that was never supplied to the repository checker requires a host-provided pre-send hook; the Standard records that enforcement boundary rather than claiming repository code can intercept uncaptured model output.
- Added `DKBWS-UPDATE-002`: consumer improvements now move through a tracked, versioned proposal record with a full Git implementation revision, optional secondary JJ change ID, deterministic form-bound payload digest, explicit approval, read-only issue reconciliation, independently recorded upstream decision, immutable release inclusion, and separately authorised consumer adoption.
- Added strict proposal and registry schemas, a versioned `standard-change` issue form, stable hidden markers, duplicate and safety checks, conforming/nonconforming fixtures, starter adaptation, and the `standard:proposal` `new`, `check`, `prepare`, `show`, `open`, `record`, and `sync --check` lifecycle. No command submits an issue, treats issue closure as acceptance, publishes a release, or changes a consumer pin.
- Recorded the Health IT Governance reader-navigation precedent as accepted `DKBWS-LINK-002` and pending immutable release without inventing an issue, release, or adoption. Migration: consumers move an ignored Markdown draft into a tracked record without inventing approval, issue, decision, release, or adoption facts; preserve the originating full Git revision; keep generated payloads disposable; bind approval only when later authorised; and retain the existing Standard pin until a release and adoption are separately authorised.
- Added conditional `DKBWS-HUMAN-004`: a seeded Human Wiki declares one canonical governing-question source and a bounded reader-source set, and every exact reader-facing repetition must use the governed `DKBWS-HUMAN-002` callout. Paraphrases, ordinary quotations, historical/source records outside that set, and subject-empty Wikis remain neutral or not applicable rather than being reclassified by textual similarity.
- Added stable source diagnostics, conforming/nonconforming/subject-empty fixtures, manifest and starter mappings, exhaustive selected-profile conformance accounting, and desktop/mobile browser proof across every discovered repetition route. Consumer-specific regexes, route names, question text, corpus counts, and renderer code are not normative implementation identities.
- Migration: seeded Human Wikis identify the canonical question source, bound the reader sources that may repeat it, wrap every exact repetition with the governed callout, and capture all discovered routes in built-output proof. Subject-empty Wikis omit the mapping and record `DKBWS-HUMAN-004` as not applicable; profile reports still materialize the result explicitly.
- Added `DKBWS-RUNTIME-002` for persistent managed previews, classified as a core control after a verified consumer port-collision incident: each service owns a stable ID and canonical loopback endpoint through a serialized, atomically published shared-register reservation; registration refuses registered and unmanaged-listener conflicts; and status requires exact registry, installation, load, HTTP, and static-marker identity agreement.
- Added the versioned `service-identity-v1` schema, project marker, hardened macOS LaunchAgent wrapper, concurrent-lock/stale-owner/atomic-write/live-listener/wrong-site HTTP-200 fixtures, Standard Production `local_service` enforcement, full-profile evidence mapping, starter adaptation, lifecycle planning, and exact registered-URL browser handoff. Ephemeral alternate-port browser verification continues to prove only `DKBWS-RUNTIME-001`.
- Migration: persistent consumers inventory the current registry, adapter, and live listener; move only their own configuration when a collision requires a new port; update every canonical URL reference together; add the project-unique marker and composite status fixtures; then prove the requested preview at the registered URL. Foreground-only consumers record `DKBWS-RUNTIME-002` as not applicable.
- Added conditional `DKBWS-LINK-002` for exact reader evidence navigation: each displayed registered source identity is an independent internal link to its exact source-register row, lists retain every identity, compact ranges link their displayed endpoints, and direct links naming official authorities or publications use registered source URLs.
- Added stable source-row anchors, visible bracket-preserving link styling, an optional idempotent migration helper, stable lint diagnostics, Unicode/fence/Markdown regression fixtures, and desktop/mobile built-output proof of keyboard focus, accessible identity, exact fragment, destination row, and containment.
- Migration: applicable Human Wikis first add stable anchors to the mapped source register, then convert visible identities into individual exact-row links, audit named authority URLs against the register, preserve local grammar and deviations, and add a representative browser journey. Upgrade planning remains read-only and automatic rewriting is optional; subject-empty, agent-only, and citation-free consumers record the rule as not applicable without inventing evidence.
- Strengthened `DKBWS-PROV-001` so every file-changing Standard Production development turn ends with its persistent changes in a JJ commit after verification and Git/Jujutsu inspection. Failed or unrun checks are disclosed in the commit and response rather than used to leave work uncommitted; no subjective “substantive work” threshold or no-change empty commit remains.
- Migration: Standard Production maintainers update shared agent instructions, maintenance guidance, and the end-of-turn helper, then apply the rule prospectively from the upgraded revision. Existing JJ history is not rewritten; Portable Core and explicit Git-only distribution/CI checkouts are unchanged.
- Added conditional `DKBWS-HUMAN-003` for dedicated, readable, trailing-column-aligned draft markers in primary navigation. The Zensical reference adapter uses SVG Repo's CC0 Pen Circle asset and verifies its tooltip, mask, and chevron-centre geometry in built output.
- Extended `DKBWS-HUMAN-003` browser proof to require vertical row centring for the draft marker and stock chevron plus absence of page overflow.
- Superseded the initial ignored-draft-only consumer proposal route with the tracked `DKBWS-UPDATE-002` record while retaining its user-authored issue form, origin preservation, scrubbed public payload, read-only duplicate search, explicit remote-submission authority, and prohibition on implicit PR, release, publication, migration, pin, or conformance authority.
- Migration: Human Wikis that expose generic draft information markers in primary navigation add a dedicated open-licensed draft-edit asset, readable status mapping, licence record, alignment rule, row-centre/overflow browser evidence, and a non-draft negative control. Wikis without navigation status markers record `DKBWS-HUMAN-003` as not applicable; equivalent renderer-native markers remain valid.
- Made `DKBWS-UPDATE-001` revision-aware: lifecycle tools load candidate and consumer inputs from exact commits, compare source and ancestry independently of version labels, expose introduced profile requirements, and block missing, unresolved, newer, diverged, or inconsistent pins.
- Fixed `DKBWS-PROV-001` and documentation-sync root discovery to remove only terminal record delimiters, preserving filesystem-significant trailing spaces; added positive final-component and negative nested-root fixtures.
- Reserved verification receipt/report paths for their declared schemas and added a negative consumer-summary fixture. Consumer starter adaptation now excludes Standard-maintainer `sync:documentation:*` and `verify:workspace` unless independently declared; CI fetches full history for revision fixtures.
- Completed the independent-consumer starter closure with consumer-owned licensing, stronger four-subcontrol security/source templates, correct `graph-shell` 2D/3D templates, fail-closed graph routes, independent representative browser routes, and mobile table overflow evidence.
- Migration: consumers reconcile `standard.revision` with its declared version before repinning; rename ad hoc `output/verification/receipt.json` summaries, emit receipt-v1 plus the paired conformance report, remove copied maintainer-only sync commands, choose a consumer licence explicitly, and regenerate graph pages from the governed hooks.
- Returned the reference entry and architecture diagrams to plain Mermaid source with renderer-default node treatment, removing diagram-level initialization and semantic class opt-ins while retaining accessible descriptions, native `basis` connectors, short top-to-bottom topology, and rendered collision checks under `DKBWS-DESIGN-001`.
