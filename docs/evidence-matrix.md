# Evidence matrix

| Claim | Support | State | Limitation |
|---|---|---|---|
| Persistent synthesis should compound rather than be rediscovered for every query. | [SRC-001](./sources.md#src-001) | Supported | Requires lint and evidence safeguards against propagated errors. |
| OKF v0.2 is the portable knowledge foundation. | [SRC-002](./sources.md#src-002) | Implemented candidate | Public schema endpoints are published through the documentation Pages site; validation still uses the pinned local schema copy. Hard validation, strict guidance, and unknown-field round-trip fixtures pass locally. |
| Human and LLM products should share canonical knowledge. | [SRC-001](./sources.md#src-001), [SRC-002](./sources.md#src-002), [SRC-011](./sources.md#src-011) | Implemented candidate | More cross-renderer and independently maintained consumer fixtures are still needed. |
| A displayed governing question should be semantically distinct and use the active accent for both its rail and text. | [SRC-009](./sources.md#src-009), [SRC-012](./sources.md#src-012) | Implemented candidate (`DKBWS-HUMAN-002`) | The reference Zensical implementation has desktop/mobile browser evidence; broader cross-renderer evidence remains to be gathered. |
| Every exact reader-facing repetition of a declared canonical governing question should use the same governed callout, while paraphrases, ordinary quotations, historical records, and subject-empty Wikis remain outside that exact-string rule. | [SRC-009](./sources.md#src-009), [SRC-021](./sources.md#src-021) | Implemented candidate (`DKBWS-HUMAN-004`) | The reference source checker and desktop/mobile Chromium journey cover the bounded reader-source set and every discovered repetition route. They do not infer semantic equivalence for paraphrases or claim separate non-Chromium or assistive-technology coverage. |
| Draft pages displayed in primary navigation should use a dedicated edit marker with readable status text, share the trailing control column with navigation chevrons, remain row-centred, and avoid page overflow. | [SRC-005](./sources.md#src-005), [SRC-009](./sources.md#src-009), [SRC-017](./sources.md#src-017), [SRC-018](./sources.md#src-018), [SRC-020](./sources.md#src-020) | Implemented candidate (`DKBWS-HUMAN-003`) | The exact Pen Circle asset and geometry are reference-adapter decisions; other renderers still need equivalent built-output evidence. |
| Ordinary entry and architecture Mermaid diagrams should use renderer-default node treatment, centre fitting surfaces, and, when all three are present, separately label Human, Agent, and Graph surfaces derived directly from canonical knowledge. | [SRC-001](./sources.md#src-001), [SRC-005](./sources.md#src-005), [SRC-006](./sources.md#src-006), [SRC-009](./sources.md#src-009), [SRC-019](./sources.md#src-019) | Implemented candidate (`DKBWS-DESIGN-001`) | `SRC-019` supports the plain-source treatment only. The three-node separation and safe centring are Standard Production reference decisions, do not authorize duplicate corpora, and are not imposed where all three surfaces are absent. |
| Zensical plus the DenchCo style should lead the reference distribution. | [SRC-005](./sources.md#src-005), [SRC-011](./sources.md#src-011), [SRC-012](./sources.md#src-012) | Candidate preferred | Cross-renderer accessibility evidence remains incomplete. |
| Graphify adds useful explicit relationships but not evidence authority; a selected Graph profile must fail closed if either real 2D/3D route is absent. | [SRC-006](./sources.md#src-006), [SRC-009](./sources.md#src-009), [SRC-011](./sources.md#src-011), [SRC-012](./sources.md#src-012), [SRC-020](./sources.md#src-020) | Implemented candidate (`DKBWS-GRAPH-001`) | Semantic extraction coverage varies by corpus; selective route runs remain diagnostic only. |
| A dedicated MCP is useful later but should not be required to read the standard. | [SRC-002](./sources.md#src-002), [SRC-007](./sources.md#src-007), [SRC-008](./sources.md#src-008) | Adopted | MCP tool surface is not yet implemented. |
| Jujutsu should be included in DenchCo Standard Production maintenance workspaces, VCS root discovery must preserve filesystem-significant path bytes, and every file-changing development turn should end with a disclosed JJ commit rather than a subjective significance decision. | [SRC-011](./sources.md#src-011), [SRC-012](./sources.md#src-012), [SRC-013](./sources.md#src-013), [SRC-020](./sources.md#src-020) | Executable candidate (`DKBWS-PROV-001`) | Static and helper fixtures prove the mechanism, while historical adherence still requires reviewable turn-commit history. Portable Core and explicit distribution/CI checkouts remain Git-only compatible; Jujutsu 0.42.0 is available upstream but not yet reference-qualified beyond the locally tested 0.39.0 boundary. |
| One MIT License is the minimal clear permission for friends to reuse the repository's original work. | [SRC-014](./sources.md#src-014) | Adopted | Third-party material and registered sources retain their own terms; the licence does not transfer ownership of the DenchCo name. |
| Shared Codex/Claude instructions should finish requested scope before offering at most three goal-linked recommendations and should park trigger-blocked work rather than repeat it. | [SRC-011](./sources.md#src-011), [SRC-012](./sources.md#src-012), [SRC-015](./sources.md#src-015), [SRC-016](./sources.md#src-016) | Implemented candidate (`DKBWS-PROMPT-001`) | Static checks prove instruction presence, import, and skill parity; model adherence remains behavioural and must be observed in consumer use. |
| Development responses that navigate Wiki content should use verified live URLs at the configured canonical origin rather than file, editor, clickable local-filesystem, or repository-relative links. | [SRC-011](./sources.md#src-011), [SRC-012](./sources.md#src-012), [SRC-015](./sources.md#src-015), [SRC-016](./sources.md#src-016) | Executable candidate (`DKBWS-PROMPT-002`) | Manifest/profile checks, managed-instruction parity, service identity, route health, and captured-draft fixtures make detected violations nonconforming. Repository code cannot absolutely intercept an uncaptured response before delivery without a host-provided pre-send hook. |
| Lifecycle comparison must use canonical source plus immutable commit and expose requirement changes even when descriptive version labels are equal. | [SRC-020](./sources.md#src-020) | Implemented candidate (`DKBWS-UPDATE-001`) | Comparison requires the pinned commit and profile history to be present locally; unresolved or shallow-history cases block for manual review. |
| A reusable consumer improvement should retain committed implementation provenance and move through separately evidenced preparation, user submission, upstream decision, immutable release, and optional adoption states without allowing issue closure or automation to grant authority. | [SRC-020](./sources.md#src-020), [SRC-021](./sources.md#src-021) | Executable local candidate (`DKBWS-UPDATE-002`) | The tracked schema, CLI, registry, fixtures, and GET-only reconciliation pass locally. They are not yet present in the current public immutable prerelease, and no issue, label, release, publication, or consumer pin change is implied. |
| Reserved verification paths must contain schema-valid receipt/report artifacts, and ordinary consumers must not inherit Standard-maintainer synchronization commands. | [SRC-020](./sources.md#src-020) | Implemented candidate (`DKBWS-VERIFY-001`, `DKBWS-VERIFY-002`) | The starter provides the governed boundary and a negative ad hoc-summary fixture; each consumer still maps its own gates and evidence. |
| A consumer starter needs complete security/source/licensing and proposal-handoff safeguards without inheriting the Standard's licence or remote-write authority. | [SRC-014](./sources.md#src-014), [SRC-020](./sources.md#src-020) | Implemented candidate (`DKBWS-SEC-001`, `DKBWS-PROMPT-001`) | The owner must still select the consumer licence and reporting channel; the Standard does not make those decisions. |
| Every registered source identity displayed in a Human Wiki should independently navigate to its exact internal source-register row, while direct links naming official publications should use registered primary URLs. | [SRC-009](./sources.md#src-009), [SRC-021](./sources.md#src-021) | Implemented candidate (`DKBWS-LINK-002`) | The reference checker and pinned Chromium journey cover individual/list/range identities, exact fragments, keyboard focus, accessible identity, visible brackets, responsive containment, and destination rows; no separate screen-reader or non-Chromium matrix is claimed. |
