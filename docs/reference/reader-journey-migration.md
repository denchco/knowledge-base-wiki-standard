# Reader journey migration

Adopt this pattern through a reviewed authoring update. The candidate does not change existing consumer pins, rewrite old content or establish adoption by availability.

The guide illustrates the existing `DKBWS-PROMPT-001` authoring policy. It offers audience/task discovery, a short substantive answer for an agreed question, progressive detail and manual review as an editorial method, without changing that requirement. There is no new conformance identifier, profile capability, semantic score or proof-obligation count. See the [writing specification](../spec/writing-style.md#reader-journey-guidance).

## New subject-bearing Wikis

A later selected immutable release may carry this advisory guide and links from its prompt and authoring policy. Availability of the present candidate supplies no production-bootstrap authority. Use actual user context and sources. Give an agreed question its answer before navigation, then develop explanation, examples and exact references. The existing canonical-question callout and source contracts continue to apply.

## Existing Wikis

A bounded editorial pass can use the following sequence. It does not add a review-record duty to every ordinary edit.

1. Confirm authority and the target's exact adopted revision. An available candidate or release is not migration authority.
2. Read the mapped authoring policy, current question, audience evidence, navigation and relevant sources. Preserve local policy and resolve file collisions through review.
3. Agree the page roles and the bounded passages to rewrite. Retain source identities, actor boundaries, obligation force, dates, conditions and uncertainty.
4. Consider a complete route from the short answer to exact evidence using the [reader-journey guide](../guides/reader-journey.md#review-the-journey). A bounded note can capture findings and unresolved issues.
5. Run the target's complete applicable checks and its required provenance/commit process. Record adoption only when separately authorised and evidenced.

Do not bulk-rewrite historical records, quotations or untouched prose. A substantive correction to evidence or to the canonical question needs its own authority and review.

## Subject-empty and older pinned paths

A subject-empty Wiki receives advisory guidance without an invented audience fact, question, answer, example or source. Its awaiting-seed state remains valid. Historical initialization plans continue to use their pinned templates; a newer skill does not impose the candidate on an older consumer.

This proposal changes no dependency lock, renderer, schema or released Documentation snapshot. The Standard's snapshot allowlist includes the guide and review for a later separately governed synchronization; adding them does not perform that synchronization. Acceptance, publication in an immutable release and consumer adoption remain separate decisions.
